⇄토큰·티켓 발급(HTTP)

⇅핸드셰이크와 종료

프레임을 누르면 상세가 열립니다. HTTP 호출과 핸드셰이크는 요청·응답 원문과 터미널에서 재현하는 curl 명령을 보여 줍니다.

말풍선에 마우스를 올리면 짝이 되는 프레임이 함께 강조됩니다.

ping/pong 프레임은 브라우저가 스스로 처리해서 여기에 보이지 않습니다.

Echo

보낸 메시지를 ws-backend가 srvTs, userId, server를 붙여 그대로 돌려줍니다. 잘못된 메시지에는 오류로 답하고 연결은 유지합니다.

Push

연결하면 기본 토픽이 바로 흘러옵니다. subscribe로 토픽·주기·크기를 바꾸고 unsubscribe로 멈춥니다. 보내는 쪽 큐가 가득 차면 서버가 메시지를 버리므로 seq가 건너뛸 수 있습니다.

공개 Push

토큰 없이 연결하는 익명 엔드포인트입니다. 읽기 전용이라 무엇을 보내도 read only 오류가 옵니다.

Chat

참가자마다 자기 토큰과 티켓으로 ws-chat에 연결합니다. 같은 방의 모두(보낸 사람 포함)에게 전달되고 다른 방에는 가지 않습니다.

아직 참가자가 없습니다 참가자를 추가하거나 데모 대화를 눌러 alice, bob, carol의 대화를 재생해 보세요.

토큰 만료

수명이 짧은 access token으로 연결합니다. 세션은 티켓이 아니라 access token의 만료 시각에 서버가 3000 token expired로 닫습니다.

거절 케이스

브라우저 WebSocket은 거절된 핸드셰이크의 HTTP 상태를 알 수 없습니다(close 1006만 보입니다). 콘솔 서버가 대신 핸드셰이크를 시도해 실제 상태를 알려 줍니다.

아직 실행 전

모니터링

게이트웨이와 서비스가 내보내는 메트릭을 콘솔 서버가 대신 읽어 옵니다. 기록은 이 화면이 열려 있는 동안만 쌓이고, 새로 고치면 비워집니다.
