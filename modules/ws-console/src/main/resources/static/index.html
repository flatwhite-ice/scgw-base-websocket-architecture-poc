토큰 없음

/ws/echo → ws-backend. 위에서 발급한 토큰으로 티켓을 받아 연결합니다. 확인: 응답에 userId(내 사용자), server(ws-backend@…), srvTs가 있고 왕복 지연이 표시됩니다.

/ws/push → ws-backend. 연결하면 기본 토픽 push가 바로 옵니다(autoSubscribe). subscribe로 토픽·주기·크기를 바꾸고 unsubscribe로 멈춥니다.

/ws/public/push → ws-backend의 익명 엔드포인트. 토큰 없이 연결해 push를 받습니다. 확인: 메시지를 보내면 read only 오류가 오고, 응답의 userId는 없습니다.

/ws/chat → ws-chat. 참가자마다 자기 토큰과 티켓으로 연결합니다. 확인: 같은 방의 모든 참가자(보낸 사람 포함)에게 메시지가 도착하고, 다른 방에는 가지 않으며, server가 ws-chat@…입니다.

TTL이 짧은 access token으로 받은 티켓으로 /ws/echo에 연결합니다. 세션은 access token 만료 시각에 서버가 3000 token expired로 닫아야 합니다.

대기

브라우저 WebSocket은 거절된 핸드셰이크의 HTTP 상태를 알 수 없어(close 1006만 보임) 콘솔 서버가 대신 핸드셰이크를 시도하고 실제 상태를 알려 줍니다.
